# Development roadmap

Effort is one experienced developer with Codex, plus part-time design/QA/operations support, in focused workdays; integration/approval waits are separate. The requested 3–5-week *functional MVP* is plausible only with narrow pilot scope and ready provider accounts. The audited gaps make a production-ready launch in 3–5 weeks unrealistic. Plan 6–8 weeks for a controlled MVP and 3–5 further weeks of hardening/pilot evidence; revise after phase 0 and rights/policy decisions.

| Phase | Objective and dependency | Small implementation tasks; modules / DB / API / screens | Tests, acceptance, effort, risks, done |
|---|---|---|---|
| 0 Audit/architecture | This package; rights and policy decisions | Validate reuse rights, pilot zones, payment rules, current tests in isolated copies, confirm architecture/ERD and threat model. No DB change. | Review signoff, unknowns logged; 2–3 days. Risk: missing business inputs. Done when scope/contracts approved. |
| 1 Scaffold | Phase 0 | New repo/CI; apps `customer/pro/admin/ops`, shared tokens/API client; Django domain skeleton; Postgres/Redis local only; base migrations; health API. | CI lint/type/build/unit green; 3–4 days. Risk: overlarge monorepo. Done with isolated dev env and no Purple Squad dependency. |
| 2 Design/home | Phase 1 | Tokens/components, responsive header/nav, homepage, category/service cards, skeletons, SEO metadata; catalog seed fixture. GET catalog. | Visual/keyboard/320px checks; 3–4 days. Risk: brand assets. Done with distinct brand and accessible screens. |
| 3 Auth/catalog/locations | Phases 1–2, provider accounts | Firebase phone exchange, secure session, roles, catalog/price versions, city/zone/address CRUD and serviceability; migrations for identity/geography/catalog; login, catalog and address screens. | Negative auth/IDOR, OTP rate tests; 4–5 days. Risk: provider setup. Done with owner-scoped APIs and configured pilot zones. |
| 4 Smart booking | Phase 3 | Holds with TTL, quote snapshots, 3-step UI, booking state machine, idempotency, reschedule/cancel; capacity/quote/booking migrations; hold/quote/booking APIs. | PostgreSQL concurrent oversell/retry/expiry tests; 6–8 days. Risk: race conditions. Done with no duplicate confirmation and clear recovery states. |
| 5 Payments/notifications | Phase 4, Razorpay/MSG91 credentials | Orders, signed webhook, reconcile, refunds, invoice, outbox/Celery/Redis, templates; payment/outbox migrations; payment endpoints and confirmation UI. | Provider sandbox and failure/replay tests; 5–7 days. Risk: asynchronous state. Done when paid/unpaid branches and retries reconcile. |
| 6 Technician | Phases 3–5 | PWA shell, profile/KYC, skills/zones/hours, jobs/accept/start/complete, inspection/quote and earnings view; workforce/inspection migrations; technician APIs. | Object permissions, upload, overlap, offline tests; 5–7 days. Risk: KYC/privacy. Done with end-to-end job lifecycle. |
| 7 Operations/dispatch | Phases 4,6 | Queue, capacity, manual dispatch, assignment checks, escalations/tickets and SLA alerts; assignment/support migrations; ops APIs and dashboard. | Parallel assignment/decline/timeout tests; 4–6 days. Risk: staffing logic. Done when staff can recover unassigned jobs. |
| 8 Admin/finance | Phases 5–7 | Catalog/pricing editor, customers/techs, permissions, refund review, ledger/payout controls, reports/audit; finance migrations and APIs; admin screens. | Balanced journal, double payout, role matrix tests; 5–7 days. Risk: tax/settlement policy. Done when finance reconciles every test booking. |
| 9 Hardening | Functional end-to-end | SAST/SCA, threat review, accessibility, load/visual tests, query/index tuning, backup restore, penetration test fixes; no planned feature schema. | `04_PERFORMANCE_AUDIT.md` and zero critical/high findings; 5–8 days. Risk: late defects. Done on evidence, not time. |
| 10 Deploy/pilot | Phase 9, domain/provider readiness | Staging/prod IaC, secrets, CI gates, migration job, worker, observability, DNS/TLS, limited zone/technician pilot and incident runbook. | Smoke/rollback/restore drills; 4–6 days + pilot observation. Risk: external approvals. Done after measured pilot acceptance and business signoff. |

Critical path: rights/policy -> phase 3 -> 4 -> 5 -> 6/7 -> 8 -> 9 -> pilot. First implementation task **after review approval**: create independent repo and CI skeleton with typed API contract and local Postgres/Redis, leaving Purple Squad untouched.
