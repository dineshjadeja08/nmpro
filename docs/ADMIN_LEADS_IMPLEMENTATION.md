# Admin alignment and operations leads

Purple Squad admin routes and screen organization were inspected as read-only reference. NammaPros keeps its own brand, code, data and APIs. The existing Admin sidebar already covered bookings, customers, technicians, catalog, finance, staff, settings and audit. This change adds Leads navigation and lead metrics, plus pending technician verification, refunds and settlements on the dashboard. Admin booking detail now exposes the existing operations cancellation and rescheduling controls to authorized roles. Customer contact details and booking addresses are masked for other admin roles.

Operations now has `/leads`, `/leads/new`, `/leads/[id]` and `/leads/[id]/edit`. Create and edit use the catalog for category and service selection, save to the server, and show the saved record. The list supports server pagination, search, filters, summary metrics and 30-second polling. Detail shows activity, owner, notes, follow-ups and the linked booking. Admin reads the same records and allows authorized staff to update status, priority and assignment. Staff admins can configure lead zone grants.

The API uses `Lead`, `LeadActivity`, `LeadFollowUp` and `OperationsZoneGrant` with migrations `operations.0004` and `0005`. Lead references are unique; mobile numbers are not unique. The API enforces role and configured zone access, masks contact data for read-only staff, validates service/category and assignments, records changes, and provides follow-up queues and in-app reminders. No customer message is sent by the reminder task.

Conversion requires a qualified lead, complete service address, active coverage, an eligible package and slot, and an accepted server-calculated price. It calls the existing hold, quote and confirmation services inside a transaction, then links the booking and marks the lead converted. A repeat conversion returns the existing linked booking. Prepaid packages are hidden while Razorpay is disabled. Local SQLite migrations were applied; deployed PostgreSQL migrations were not.

Checks passed: Django system and migration checks, focused Python checks, TypeScript checks, and Admin and Operations production builds. No automated test suite or live provider call was run. Manual verification remains needed for multi-user role and zone boundaries, contact masking, follow-up scheduling/reminders, live UI flows, and concurrent conversion on PostgreSQL. Booking conversion cannot be demonstrated until service coverage, pricing and appointment slots are configured. Production deployment and public booking remain unchanged.
