# Phase 7 summary

Prepared separate Vercel builds for web, technician, admin, and operations; private apps have `noindex` metadata and headers. Public SEO has canonical metadata, a catalog-backed sitemap, and private-route exclusions. All apps have loading/error boundaries and icons.

The Django API now supports development, staging, and production settings with explicit HTTPS origins, separate CSRF origins, TLS Redis, PostgreSQL, private GCS media, short database connections, secure cookies, request IDs, JSON logs, optional Sentry, and fail-closed feature flags. Staging OTP now uses the provider. Payment collection, public booking, new zones, automatic dispatch, and WhatsApp are disabled by default in managed environments; live payouts cannot be enabled.

Infrastructure files include a multistage non-root Gunicorn image, pinned direct runtime dependencies, Cloud Build, approval-gated Cloud Run service/job scripts, a separate migration job, private bucket and Cloud SQL backup configuration scripts, starter alert definitions, and configuration-only GitHub Actions. Periodic work runs through a short-lived Cloud Run Job triggered each minute; no always-on Celery worker is assumed. The operator must review job frequency and costs before deployment.

Checks: Django system check, migration consistency, Python compilation, focused Ruff checks, four Next.js builds, Vercel JSON validation, shell syntax validation, and a synthetic staging settings import. Docker image build and real infrastructure checks were unavailable locally. `check --deploy` also surfaced unrelated installed Purple Squad checks; no Purple Squad files were changed. No automated tests, live transactions, cloud mutations, DNS changes, or production deployment were performed.

Blocked or unverified: domain ownership and DNS, service credentials, real Cloud SQL/Redis/GCS/IAM connectivity, backup and alert activation, signed URL service-account signing, worker behavior under Scheduler, frontend authentication on actual domains, booking/payment/refund/settlement acceptance, invoice issuance policy, and live payouts. Runtime versions are pinned in a transitive lock generated from the local Python 3.12 environment; Linux wheel resolution, hashes, and a container image digest remain prelaunch work. See [deployment guide](DEPLOYMENT_GUIDE.md) and [launch checklist](LAUNCH_CHECKLIST.md).
